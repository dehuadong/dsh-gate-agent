# 领域文档

工程技能在探索代码库时如何消费本仓库的领域文档。

## 探索前先读

使用项目指令指向的文档入口 [`docs/AGENTS.md`](../AGENTS.md) 定位领域术语表与适用的设计、决定和约束。路径由管理根（仓库根）解析，不假定文档都在 `src/` 下。

- 根 `GLOSSARY.md`：领域术语表。本仓库为单上下文项目，没有 `GLOSSARY-MAP.md`；术语确定时由 `domain-modeling` 创建术语表。
- 长期技术设计与决定：`.agents/notes/` 的 Agent Note；逐根读取时按 `write-agent-notes` Skill 传 `--root <path>`。
- 缺失的必需设计或决定输入，或范围相互冲突时，报告具体缺口与受影响工作。

## 使用术语表词汇

输出中出现领域概念（工作项标题、重构提案、假设、测试名）时，使用 `GLOSSARY.md` 定义的术语，不漂移到术语表明确避免的同义词。概念不在术语表中时，说明这是需要 `/domain-modeling` 的真实缺口，或是在发明项目不用的语言。

## 标记决定冲突

输出与适用决定矛盾时，指出配置的来源并说明冲突：

> _与关于 `<主题>` 的现行 Agent Note 冲突——因为……需要重访该决定。_
